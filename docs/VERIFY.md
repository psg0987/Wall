## 배포 기록 규칙 (RT-DEPLOY-DOC-01, 2026-10-24)

이 저장소의 '배포'는 세 가지로 나눠 따로 적는다.

1. **GitHub Pages 자동 게시**: main에 push할 때마다(병합·문서만 바뀐 push 포함) GitHub가 'pages build and deployment'를 자동 실행해(Checkout → Upload artifact → Deploy to GitHub Pages) 그 커밋의 저장소 파일을 그대로(`.nojekyll`) `https://psg0987.github.io/Wall/`(배포 환경 `github-pages`)에 다시 올린다. 코드를 빌드하지 않는다.
2. **웹 게임 빌드 배포**: 새 게임 빌드(`python3 build/build.py` → `python3 build/site.py`가 만드는 저장소 루트 `index.html`)를 main에 커밋해 1번으로 게시하는 것. 게임 코드(`src/`)가 main에 들어가도 `index.html`을 바꾸지 않으면 웹 게임은 바뀌지 않는다.
3. **APK 배포**: 안드로이드 APK를 빌드해 내보내는 것.

적는 법:
- main push마다 Pages 자동 게시의 실행 ID·배포 ID·결과·시각을 적는다. 확인하지 못했으면 '확인 못 함'과 이유를 적고 추정하지 않는다.
- 웹 게임 빌드 배포는 `index.html`이 바뀐 커밋, 그 sha256, 들어간 작업 ID를 적는다. `index.html`이 바뀌지 않았으면 '웹 게임 빌드 배포 없음(`index.html` 그대로)'이라고 적는다.
- APK는 버전·sha256·출하 여부를 따로 적는다.
- 셋을 묶어 '배포 안 함'·'배포 없음'이라고 쓰지 않는다. 이 규칙 전에 쓴 기록의 '배포 안 함'·'배포 없음'·'미배포'는 수동 웹 게임 빌드·APK 배포가 없었다는 뜻이고(브랜치 단계 항목의 '미배포'는 그 브랜치가 main에 들어가기 전 상태), 그 무렵 main push의 Pages 자동 게시는 아래 이력에 적은 것만 사실로 본다.
