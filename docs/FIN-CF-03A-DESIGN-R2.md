### 2-3. 호출처별 기록 (분류·현금 대금)

`absorb(a,t,paidVal,cashPaid)` — 맨 앞에서, 소유 관계와 t.cs·t.D를 바꾸기 전에 기록한다.


`t.own["c"+a.id]`는 네 호출처 모두에서 absorb 진입 시점까지 보존된다(G.merge·maTick·offer는 인수 회사 외 주주만 0으로 만들고, G.liq는 100% 그대로 들어온다). 그래서 호출처가 분류를 따로 넘길 필요가 없다. `ctl` 필드는 쓰지 않는다(5-1: `ctl`은 그룹 최종 지배자라 인수 회사 자신을 가리키지 않는다).

### 2-4. fqDerive 식 (03A)

```javascript
st  = !prev ? null : q.d <= c.acd ? "old" : prev.d <= c.acd ? "part" : "full"
R   = (st === "part" || st === "full") && c.acr && c.acr[q.d] || null
ncA = R ? R.aD + R.iD + R.lD + R.hD : 0          // 비현금 부채 증가 (gr 제외)
maN = R ? R.aC - R.aP : 0                         // 인수 순현금 (외부)
inN = R ? R.iC - R.iP : 0                         // 자회사 흡수·투자회수 순현금 (내부)
cff = dD + nc - ncA - dv + iss                    // nc: FIN-CF-01, iss: FIN-CF-02 (변경 없음)
oth = dc - cfo + capex - cff - maN - inN
```

반환 객체에 `st, ncA, maN, inN, aD, aP, aC, iD, iP, iC, lD, hD`를 더한다. 기존 키 `cff`·`oth`는 보정된 값이 되므로 화면의 차입 증감(`cff+dv−iss`)·재무활동·기타·투자 매매는 식 변경 없이 새 값을 쓴다. `q.gr`은 쓰지 않는다.

### 2-5. 등식

```
dc = cfo − capex + cff + maN + inN + oth
```

증명: oth 정의를 대입하면 cfo − capex + cff + maN + inN + (dc − cfo + capex − cff − maN − inN) = dc. 현행과의 관계: cff = cff_현행 − ncA, oth = oth_현행 + ncA − maN − inN. 영업활동·설비투자·FCF는 바뀌지 않는다.

이 등식은 정의상 항상 성립하므로 분류가 맞다는 증거가 되지 못한다. 분류 정확성은 7절 B 테스트로 따로 검증한다.

#4에서 pending을 비우는 근거: qBack은 불러온 시점의 부채·현금에 축소 계수를 곱해 합성 행을 만든다. 저장 전 인수로 들어온 부채는 이미 그 합성 직전 행 안에 있으므로, pending을 남겨 다음 결산에서 빼면 같은 부채를 한 번 더 빼게 된다. 실제 게임 행으로 확인했다(부록 A-2 [D]): pending을 남기면 첫 실제 행 차입 증감 −1,156.80, 비우면 −39.00(합성 직전 행에서 오는 기존 오차). 비운 사실은 ◐ 부분 기록 표시로 드러난다.

### 5-2. 분류 규칙 (제안)

**거래 직전 인수 회사의 직접 지분이 과반(> 50%)이면 내부 흡수, 아니면 외부 인수.**

근거: 화면은 회사별 재무제표다(R1-1-1, 유지). 회사별 재무제표에서 "자회사 흡수·투자회수"는 그 회사가 가진 자회사 투자를 거둬들이는 거래다. 인수 회사가 지분을 갖지 않은 자매 회사는 그 회사의 투자가 아니므로 회사 입장에서는 새로 들여오는 사업이다.

| 거래 | 직접 지분 | 분류 | 표시 행 |
|------|----------|------|--------|
| G.liq 100% 자회사 | 100% | 내부 | 자회사 흡수·투자회수(순현금) |
| G.merge, 인수 회사가 60% 가진 상장 자회사 | 60% | 내부 | 자회사 흡수·투자회수(순현금) |
| maTick, 자기 60% 자회사 + 나머지 40% 현금 매입 | 60% | 내부 (iP = 현금 지급) | 자회사 흡수·투자회수(순현금) = iC − iP |
| G.merge, 플레이어가 지배하는 자매 회사 (K1·K10) | 0% | 외부 | 인수 순현금 |
| maTick·offer·G.merge, 다른 그룹 회사 | ≤ 50% | 외부 | 인수 순현금 |

대안은 그룹 기준(거래 직전 대상의 최종 지배자가 인수 회사의 최종 지배자와 같으면 내부)이다. 이 경우 K1·K10은 "자회사 흡수·투자회수"로 가지만 인수 회사의 자회사가 아니어서 행 이름과 맞지 않는다. 최종 결정은 GPT-6 판단 사항이다(9절 G1). 어느 쪽이든 장부 구조·식·테스트 틀은 같고 absorb 첫 줄의 판정식만 다르다.

## 7. 항목별 독립 테스트 명세

새 테스트 파일 `tests/t_fincf03_acq.js`(구현 승인 후 작성). 공통 측정 도구는 테스트 안에서만 쓰고 게임에 넣지 않는다.

- **쓰기 추적기**: 대상 회사의 `cs`·`D`에 접근자를 걸어 모든 쓰기의 증감과 호출 위치(스택의 게임 함수 이름)를 기록한다(감사 K6, 부록 A-1과 같은 방법). 회사 결산 순간의 원값도 남긴다.
- **호출 측정**: 각 거래 함수 호출 직전·absorb 진입 직전·직후의 인수 회사·대상 회사 `cs`·`D`·지분.
- **부채 쓰기 위치 분류표**: 현금 차입(overflow, 회사채, 대출 등)과 비현금(absorb 승계, G.tender LBO, hqQ 숨은 부채, earn kd gr, ch11x 감면)을 호출 위치로 나눈 고정 목록. **목록에 없는 위치의 부채 쓰기가 나오면 실패**한다(새 비현금 경로를 놓치지 않기 위한 완전성 검사).

허용 오차: 장부 기록 대 측정값 1e−9(같은 부동소수점). 화면 값 대 원값 계산은 행 반올림 때문에 차 하나에 ±1.0(r1이 10 이상을 정수로 반올림, 두 행의 차).
