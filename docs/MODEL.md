# 모델 문서 (MODEL.md)

게임이 계산하는 공식과 가정을 적는 곳이야. 코드를 바꾸면 이 문서와 테스트를 같은 변경에서 고친다.
단위: 금액은 억 원, 금리는 연 %, 한 분기 = 90일.

## 1. 분기 결산 (`earn`, src/sim.js)

회사마다 정해진 날(분기마다 한 번) 아래 순서로 계산한다. 은행(kd=1)·보험(kd=2)은 다른 점이 셋 있다: 영업이익 공식이 다르고, 결산에서 이자비용을 따로 빼지 않으며(조달 비용이 영업이익 공식 안에 있음), 성장에 드는 돈을 현금 대신 부채(예금)로 댄다.

### 입력
| 기호 | 뜻 |
| --- | --- |
| A | 영업 자산 |
| cash | 현금 |
| gw | 영업권 |
| D | 총부채 = 은행 대출 + 회사채 + 플레이어 대여금(pa) |
| bond, cpn | 회사채 잔액, 표면금리(연 %) |
| rating | 신용등급. 부채/자본 비율(은행은 9로 나눔)이 0.3 / 0.6 / 1 / 1.6 / 2.5 미만이면 AAA / AA / A / BBB / BB, 그 이상 B, 자본 ≤ 0이면 D. 가산금리 SPR = 0 / 1 / 2 / 3.5 / 5.5 / 8 / 3 (%p) |
| prime | 기준금리(연 %) |
| csp | 신용 스프레드 지수(기본 1.8) |
| tax_rate | 법인세율(설립 국가별, 기본 0.35) |
| nol | 이월결손금 |
| payout | 배당성향 |
| g | 연 성장률 |
| op | 영업이익(이 문서 2장의 영업 모델이 정함. 결산 검산에서는 입력으로 받는다) |
| eqi, dr | 이번 분기에 쌓인 지분법 이익(20% 이상 보유 회사 몫), 받은 배당(20% 미만 보유) |

### 계산 순서
```
spread_mult = clamp(1 + (csp / 1.8 - 1) × 0.6, 0.7, 2.5)
bank_loans  = max(0, D - bond - pa)
interest    = bank_loans × (prime + SPR[rating] × spread_mult) / 400
            + bond × cpn / 400
            + pa × prime / 400                      (플레이어 대여금 이자는 플레이어 현금으로)
int_income  = cash × (prime - 2) / 400              (분기 초 현금 기준)
cash_profit = op - interest + int_income
ga          = gw × 0.025                            (영업권 분기 상각 2.5%)
pretax      = cash_profit - ga
tax         = pretax > 0 이면 (pretax - 이월결손금 사용분) × tax_rate, 아니면 0 (손실은 이월결손금에 더함)
              ※ 80% 이상 지분을 가진 모회사가 있으면 연결 납세(모회사 결손금 사용)
net_income  = pretax - tax + eqi + dr
dividend    = max(0, cash_profit - tax + dr) × payout   (배당 금지 상태면 0)
cash       += cash_profit - tax - dividend
gw         -= ga
growth      = A × g / 4;  A += growth
cash       -= growth (성장 > 0)  또는  cash += 0.9 × |growth| (축소: 자산을 10% 손해 보고 매각)
cash < 0 이면 부족분만큼 D 증가, cash = 0
회사채 만기일이 지났으면: bond = 0 (은행 대출로 갈아탐, D는 그대로). 플레이어가 가진 그 회사채는 액면으로 현금 상환
AI 회사, 등급 BB 이상, 회사채 없음: 분기마다 5% 확률로 min(은행 대출 × 0.5, 자본)만큼 회사채로 바꿈
              (표면금리 = prime + SPR + 1, 만기 5~10년, D는 그대로)
현금 정리(sweep): AI 회사는 설정이 켜져 있으면, 플레이어 회사는 '강제'(sweep = 2)일 때만.
              목표 현금 tc = A × 0.06 (은행 0.08, 보험 0.25)
              cash > 1.5 × tc 이고 D > 0 이면 min(은행 대출(은행·보험은 D), cash - tc)만큼 갚음
```
분식회계(`c.cook`)가 걸린 분기는 보고 순이익을 |순이익| × 1.2 + A × 0.004로 부풀리고 표시(`c.fr`)를 남긴다. 현금은 그대로라 이 분기는 돈 보존 검사에서 뺀다.

### 부실 처리 (이번 수정)
- 순이익 < 0 이고 부채/자본 > 1.2(은행 12)인 분기가 4번 연속이면 자산을 손상 처리한다: 자본이 자산의 -30%가 될 때까지 A를 줄인다(최소 A의 20%는 남김).
- **손상차손은 그 분기 순이익에 반영한다**(EPS, 재무제표 '자산 손상차손' 줄, 모회사 지분법 이익에도 반영). 세금 효과는 없다고 단순화한다.
- 자본이 자산의 -25% 아래면 법정관리: 기존 주주 지분 소멸, 회사채 40%만 남김, 부채를 줄여 자본 = 자산의 15%로 재출발. **이 부채 감면은 출자전환(자본 거래)으로 보고 순이익에 넣지 않는다**(결산 기록 `er.cap`). 두 번째 법정관리는 상장폐지.

### 은행 대손 (RT-BANK-001, `ch11x`·`woBook`, src/sim.js)
- 차입 회사의 **첫 번째** 법정관리 날, 그 회사 은행 대출(`loanOf` = D − 회사채 − 플레이어 대여금)의 30%를 대출 은행의 자산 A에서 바로 뺀다. 같은 금액을 그 은행의 대기 대손액 `woq`에 더한다.
- 은행이 **그 뒤 처음 실행하는 결산**에서 대기 대손액을 대손상각비로 순이익에 한 번 반영하고 `woq`를 0으로 비운다. 하루 안에서는 회사 번호 순서로 결산하므로, 대손 날이 은행 결산일이면 은행 결산이 아직 안 돌았을 때만 그날 결산에 들어가고, 이미 돌았으면 다음 분기 결산에 들어간다. 대손 두 건이 한 결산 전에 생기면 합쳐서 한 번 반영한다.
- 반영 방식은 자산 손상차손과 같다: **세후 순이익에서만 뺀다.** 세금·이월결손금·배당(현금 이익 기준)은 이미 계산이 끝나 바뀌지 않는다. 함께 고치는 것: 분기 기록 `er.ni`·`er.wo`, EPS 기록(`eh`), 연간 순이익(`yni`), 20% 이상 보유한 회사의 지분법 이익, 분기 재무 기록 24번째 칸 `wo`(손익계산서 '대손상각비' 줄, 해당 분기가 있을 때만 보임).
- 손상차손처럼 결산 날의 EPS 서프라이즈(주가 점프)는 반영 전 순이익으로 계산한다. 반영 뒤 순이익을 쓰는 것: 부실 카운터(`ds`), 자동 경영, 실적 로그, 분기 재무 기록, 그리고 EPS 기록을 거쳐 목표주가(`tgCalc`의 최근 4분기 EPS). 그래서 대손은 결산 뒤 주가에 서서히 반영된다.
- 은행이 법정관리로 받는 지분(`ch11x`의 출자전환)은 대손과 상계하지 않는다. 취득원가 `bs` = 0 그대로, 대손액은 지분 가치와 무관하게 대출의 30%.
- 대손충당금 `llr`은 건드리지 않는다(아래 알려진 단순화 1번).
- 저장 호환: `woq`는 회사 객체에 저장된다. 없으면 0(`v8prep`이 새 게임·불러오기·매달 점검 때 채움). 수정 전 버전 저장 파일에서 이미 일어난 대손은 소급 반영하지 않는다(그 저장 파일에는 대기 금액이 없음).
- 은행이 다음 결산 전에 사라지면(상장폐지·흡수) 대기 대손은 순이익에 반영되지 않는다. 자산 감액은 이미 반영돼 있다.
- 현금흐름표(재무 탭 '현금흐름', `fqDerive`, src/ui1.js): 대손상각비(`wo`)와 자산 손상차손(`imp`)은 현금이 나가지 않는 비용이라 영업활동 현금흐름에 다시 더한다(RT-BANK-001-R1). 영업활동 현금흐름 = 순이익 − 지분법 이익 + 영업권 상각 + 감가상각 + 손상차손 + 대손상각비. '기타·투자 매매'는 현금 증감에서 영업·투자·재무를 뺀 나머지라 따라서 바뀌고, 잉여현금흐름도 같이 맞아진다. 이 칸이 없는 옛 기록은 0. 탭에서는 이 조정이 '손상·대손상각(비현금 조정)' 줄(손상차손 + 대손상각비, 양수)로 보여서 '순이익 + 감가상각 + 지분법·상각 조정 + 손상·대손상각' = 영업활동 현금흐름이 된다. 이 줄은 탭의 분기들 가운데 손상차손이나 대손상각비가 있는 분기가 하나라도 있을 때만 나온다(손익계산서의 '자산 손상차손'·'대손상각비' 줄과 같은 규칙).

### 검산 항등식 (tests/t_clean_surplus.js)
```
Δ(A + cash + gw - D) = net_income - eqi - dr - dividend + capital_transactions + bank_writeoff_reported (er.wo)
```
eqi와 dr를 빼는 이유: eqi는 다른 회사 이익의 몫이라 현금이 아니고, dr는 배당을 받을 때 이미 현금에 들어왔다.
er.wo를 더하는 이유(dr의 거울상): 은행 대손은 차입 회사 법정관리 날 이미 자산에서 빠졌고(분기 중간), 그 분기를 마감하는 은행 결산이 비용으로 순이익에 넣는다. 그래서 그 결산의 순이익은 er.wo만큼 낮지만 결산 안에서 자본은 그만큼 움직이지 않는다. 구간 [법정관리 직전 → 은행 다음 결산]으로 보면 추가 항 없이 맞는다(tests/t_bank_writeoff.js). 이 항이 다른 불일치를 가리지 못하게, 테스트는 대손마다 자산 감액 = 대기 금액, 결산마다 보고액 = 대기 금액, 시드마다 대손 합 = 보고 합 + 대기 합도 확인한다.
보유 주식(다른 회사 지분)은 시가로 평가하므로 이 식에서 뺀다.

### 명세 대조 테스트 (tests/t_close_spec.js)
일반 AI 회사(은행·보험, 80% 모회사, 분식, 회사채 만기·발행, 손상·법정관리 분기 제외)의 결산을 결산 직전 상태와 보고된 영업이익에서 출발해 위 공식으로 다시 계산하고, 게임 값과 항목별로 비교한다(상대오차 1e-9).
2026-10-17: 고정 시드 2개 × 720일, 결산 7,381번 전부 일치. 실제로 돈 갈래와 횟수: 영업권 상각 68, 이월결손금 사용 68, 손실을 결손금으로 적립 82, 지분법 이익 166, 받은 배당 295, 배당 0 157, 현금 정리 594, 현금 부족분 차입 57.
아직 한 번도 안 돈 갈래(검증 안 됨): 성장률 음수(자산 매각), 플레이어 대여금, 현금 정리가 대출 잔액에 막히는 경우.

   - **R2 — 은행 소멸 시 미보고 대손.** 은행이 대손 발생 후 첫 결산 전에 소멸하면 `woq`가 순이익에 반영되지 않을 수 있음. 분류: 미해결 결함 후보. 이번 병합 차단 사유는 아님. (현재 동작 설명: 위 '은행 대손' 절)
   - **R3 — EPS 서프라이즈 기준 차이.** EPS 서프라이즈와 즉시 주가 반응이 `woBook()` 이전 실적을 사용하고, 확정 EPS는 대손 반영 후 실적을 사용함. 분류: 미해결 회계·표시 정책 검토. 이번 병합 차단 사유는 아님. (현재 동작 설명: 위 '은행 대손' 절)
   - **REG-01 — imp + wo 동시 발생.** 같은 은행 결산에서 손상차손(`imp`)과 대손상각비(`wo`)가 함께 나오는 경우의 회귀 테스트. 상태: **테스트 추가됨(2026-10-18, 브랜치 rt-reg-01, 병합 전)** — `tests/t_reg01_bank_imp_wo.js`, 사례 A(손상만)·B(대손만)·C(둘 다)·D(둘 다 없음)와 사례 C의 쌍둥이 4개. 기대값은 입력값·회계 항등식·코드 규칙에서 계산(실행 결과를 복사하지 않음). **한계:** 사례는 합성 상태(`ds`·`eqi`·자본을 설정)이며 자연 플레이에서 은행 손상은 시드 12345/777/20261016 × 720일에서 0번이라 '플레이에서 도달 가능함'은 증명하지 않음. 이번 범위 밖: 대손 자체가 `ds` 연속 기록을 만드는 경우(`ds`↔대손 연동), 결산 두 번에 걸친 흐름(실제 이전 분기 행), 은행이 그 결산에서 소멸하는 경우, 차입 회사 여러 곳, 플레이어 소유 은행, 지분 80% 이상 모회사. 분류: 회귀 테스트 추가됨, 위 범위 밖 사례는 미검증.
   - **REG-02 — 조 단위 표시 경계.** 현금흐름표가 1만억 이상 금액을 조 단위 소수 둘째 자리로 표시할 때 반올림 오차와 행 합계가 올바른지 검증하는 테스트가 아직 없음. 분류: 미검증 화면 회귀 테스트 후보. 이번 병합 차단 사유는 아님.
   - **FIN-CF-01 — 법정관리 부채 감면이 재무활동 현금흐름과 기타 항목에 반영되는 문제.** 현재 `fqDerive`(src/ui1.js)는 분기 재무활동 현금흐름을 `cff = dD − 배당 + 증자`(`dD` = 분기 말 부채 − 이전 분기 말 부채)로, 기타·투자 매매를 `oth = 현금 증감 − 영업CF + 설비투자 − cff`로 계산한다. 법정관리(`ch11x`)의 부채 감면은 현금이 오가지 않는데(자본 거래 `er.cap`으로 자본에만 기록) 부채 변화 `dD`에는 들어가므로, 그 분기의 '차입 증감(재무활동)'이 감면액만큼 작게 보이고 같은 금액이 '기타·투자 매매'에 반대 부호로 나타난다. 분기 재무 기록(24칸)에는 `cap` 칸이 없어 `fqDerive`가 감면액을 구분할 수 없다. 근거: 실제 플레이 로그 `verify/rt-bank-001/fix_row_run_2026-10-17.log` 48·52행(JYNR, 부채 변화 −848.4240·현금 +32.0693·재무활동 −848.0·기타 +920), REG-01 합성 사례 C(감면 `cap` 379.2208 = 부채 971.7482 → 592.5273). 법정관리 분기이면 손상차손이 없어도 해당하므로 REG-01 범위만의 문제가 아님. 분류: **미해결 회계 모델 검토 항목** — 확정된 결함이 아님(현금흐름표를 어떤 모델로 볼지의 정책 결정이 먼저). **이번에는 수정하지 않음**(게임 코드·기대값 그대로). REG-01은 `cff`·`oth`·`cap`·`dD`를 기록만 하고 절대값 PASS/FAIL 판정에 쓰지 않으며, 이 항목이 해결돼도 REG-01 판정은 바뀌지 않는다. 이번 병합 차단 사유는 아님.
   - **참고 — 영업현금흐름 규칙 `cfo = 현금이익 − 세금 + 받은 배당`.** REG-01은 이 식을 '현행 게임 모델의 계산 규칙' 검증으로 분류한다(회계 항등식이 아님). 통과는 게임이 자기 모델대로 계산한다는 뜻이지 모델이 옳다는 뜻이 아님.

## 2. 영업 모델 (요약, 아직 검증 전)
일반 회사: `op = A × (업종 기본 마진 + 0.5 × (수요 증가율 - 설비 증가율) + 0.003 × 경영 + 0.03 × (g - 0.04) + 점유율 50% 초과 시 0.004 + 숨은 경쟁력) × (1 + 실적 충격)`, 이후 R&D 비용·생산성·사건 보정.
이 부분은 게임 설계 가정이라 "정답"이 없다. 검증은 현실 시장 통계(Gemini 조사)와 범위를 비교하는 방식으로 한다.
